# Tabs

Tabs switch between related panels of content within the same view, one panel visible
at a time, without navigating to a new page. It uses Bootstrap's Tab behavior
internally.

## Variants

- **Tabs** (default) — the classic boxed tab style (`.nav-tabs`).
- **Pills** (`variant="pills"`) — rounded, filled selected state (`.nav-pills`).
- **Underline** (`variant="underline"`) — a minimal underline on the selected tab
  (`.nav-underline`).
- **Vertical** (`vertical`) — lays the tablist out as a column beside its
  tab-content, with `aria-orientation="vertical"`. Can combine with any variant
  above; the story below uses `pills`, matching Arizona Bootstrap's own example.
- **Fill** (`fill`) / **Justified** (`justify`) — `.nav-fill`/`.nav-justified`,
  proportionately filling or equally dividing the available width across items.

The two implementations get their interactivity from different places, same as
Accordion: `components-html` renders Arizona Bootstrap's real
`data-bs-toggle="tab"`/`"pill"` markup, and the actual tab-switching behavior comes
from Bootstrap's own Tab plugin (part of the JS bundle loaded into this Storybook,
same as Accordion's collapse behavior); `components-react` wraps `react-bootstrap`'s
own `Nav`/`Tab.Container`/`Tab.Content`/`Tab.Pane`, which manages switching, focus, and
ARIA (`aria-selected`, `role="tab"`/`"tabpanel"`) itself, no Bootstrap JS involved.

**Not `react-bootstrap`'s higher-level `Tabs`/`Tab` shorthand** — that always wraps
each tab in `<li role="presentation">` internally, with no prop to configure it away.
Arizona Bootstrap has a custom override rule scoped to a *different* component's
markup, `.nav.nav-pills.flex-column > li` (in `scss/override/_nav.scss`, meant for
<a href="./?path=/docs/primary-components-navigation-nav--docs" target="_top"><code>Nav</code></a>'s "Vertical Pills" nested-menu variant, which
really does use `<li>`) — that selector doesn't know the difference, and matched this
component's `<li>` wrappers too whenever `variant="pills"` and `vertical` were both
set, adding borders and negative margins that were never meant for a tabbed interface.
Verified directly: switching to `Nav`/`Nav.Link` with no `Nav.Item`/`<li>` wrapper (also
matching Arizona Bootstrap's own real vertical-tabs markup, which uses bare `<button>`s
in a `<div>`, not `<ul>`/`<li>`) removed the extra styling entirely.

## Not covered by this component

Arizona Bootstrap's navs-and-tabs docs page also has a few other `.nav`-based patterns
that this component deliberately doesn't cover, because they're a different,
non-interactive building block — a plain, static link list, not the dynamic
tab-panel-switching interface above (no `data-bs-toggle`, no `tab-content`/`tab-pane`).
See <a href="./?path=/docs/primary-components-navigation-nav--docs" target="_top"><code>Nav</code></a> for those: plain Vertical, the
Arizona-custom Vertical Pills (a nested, multi-level pills menu), and the
Arizona-custom Utility Links.

## Anatomy

The tabs' contract (`tabs.contract.json`) records each tab's padding and its label's weight and colors, at rest, on hover and when selected. Every value comes from Arizona Bootstrap's compiled CSS. Two of its colors aren't in the contract yet, the Tabs style's border and the Pills style's selected fill: Arizona Bootstrap uses its gray neutrals for them rather than brand colors, and those are a design decision still to make.
