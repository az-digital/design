## Primitives

Raw values, grouped by type of measurement, that semantic and component tokens point at. Each name is the value itself, such as `az.dimension.50` for 50px, so a primitive never changes meaning. Use semantic or component tokens in designs and code, not primitives.

## Semantic colors

Purpose-based aliases onto the brand palette (`az.color.semantic.*`), named for what a color is for, never for what it looks like. `surface.*` holds background colors that content sits on. `surface.brand` is the surface that follows the brand: Blue (Arizona's primary color 2) by default, and a theme can point it at another primary color. Each surface has an on-color group, such as `on-brand.*`, for the text, icons and focus rings that sit on it; a theme that repoints a surface repoints its on colors with it. Every value traces back to a brand color, so a design decision changes in one place. Use these, not brand colors, in components and production UI.

## Component tokens

Tokens scoped to a single component (`az.component.<component>.*`), so each component's design decisions are explicit and inspectable instead of implicit in its CSS. Structure shared by all of a component's variants sits at its root; each variant (a style like `solid` or `outline`, or a size) holds only what it changes. Colors point at semantic tokens; sizes, weights, and opacities point at primitive values.

Expand a component to see its tokens by group, or search across every component by name, type, alias, or value (e.g. `semantic.action.default` finds every component token built on it). Each component's Docs page and the **Tokens** tab on its stories show the same tokens in context.
