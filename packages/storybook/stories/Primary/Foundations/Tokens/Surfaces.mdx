# Surfaces (proof of concept)

> **Placeholder values.** Every dark mode color here is a stand-in to prove how surface modes work, not a design decision. Dark mode values need to come from design, in Figma.

A **surface** is the background a page or section sits on. Dark mode is one surface; the design system's approved brand backgrounds, like AZ Blue, are others. Components don't need to know which surface they're on: they read semantic tokens, and each surface gives those tokens its own values.

## How it works

- **Brand colors and primitives never change.** Arizona Red is always Arizona Red.
- **Semantic tokens change per surface.** `az.color.semantic.action.default` is Arizona Red on a light surface and Rain on a dark one, because red is only 2.4:1 against Tinta. The dark values live in `tokens.dark.json`, one file per mode, the way Figma variable modes import them.
- **Component tokens never change either.** They alias semantic tokens, so they follow the surface. A component token that aliases a brand color directly can't follow it: Button's label color used to alias white, and now aliases `az.color.semantic.on-action.default`.

## Using a surface

Put `data-az-surface` on the page or any section, and load `tokens.css` and `tokens.dark.css`:

```html
<section data-az-surface="dark">…</section>
```

- `dark`: always dark.
- `auto`: dark when the visitor's operating system is in dark mode.
- `light`: light, for example a light section inside a dark page.

Every library follows: the Arizona Bootstrap, React, and Quickstart buttons through the token-based button CSS, and web components through the tokens their styles read. Use the **Theme** toolbar (Storybook's themes addon) to see any story on a dark surface; its Dark values are the placeholders above.
